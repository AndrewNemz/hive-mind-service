# AGENTS.md — Правила для AI-агента в проекте

## 1. Общие положения
Этот документ описывает правила, которые AI-агент (например, Continue в режиме Agent/Plan) обязан соблюдать при работе с данным репозиторием.  
Все действия агента должны быть безопасными, предсказуемыми и контролируемыми пользователем.

## 2. Категорические запреты
Агент **НИКОГДА** не должен выполнять следующие действия без **явного письменного подтверждения** пользователя в чате:

- **Читать файлы, содержащие секреты и учётные данные.**  
  К ним относятся: `.env`, `.env.*`, `*.pem`, `*.key`, `config.secret.*`, а также любые другие файлы, которые могут содержать пароли, токены, API-ключи.  
  Если для выполнения задачи агенту нужна информация из таких файлов, он обязан сначала спросить разрешение и объяснить, зачем это нужно.

- **Изменять любые файлы в проекте.**  
  В том числе: исходный код (`*.go`), конфигурации, `README.md`, `go.mod`, `go.sum`, файлы миграций, скрипты и т.п.  
  Агент может только **предложить** изменения и показать их в виде diff или текста. Запись в файл выполняется только после команды пользователя, например: «Примени изменения».

- **Пересобирать бинарники и запускать сборочные команды.**  
  Запрещено выполнять `go build`, `go install`, `go generate`, `make`, `docker build` и любые другие команды, которые создают или изменяют исполняемые файлы, без отдельного разрешения.

- **Выполнять команды, изменяющие состояние системы.**  
  Например: `rm`, `mv`, `chmod`, `git commit`, `git push`, установка пакетов и т.п.  
  Разрешены только команды чтения: `ls`, `cat` (кроме файлов с секретами), `grep`, `git status`, `git log` и аналогичные.

## 3. Порядок работы
Агент должен придерживаться следующего алгоритма:

1. **Анализ в режиме «только чтение».**  
   По умолчанию агент работает в режиме Plan (read-only). Он изучает код, структуру проекта и формирует ответ.

2. **Показ результата.**  
   Если задача связана с генерацией текста (например, README) или изменением кода, агент сначала **показывает полный текст или diff** в чате.  
   Пользователь может попросить правки, и агент обязан их внести в предпросмотр.

3. **Запрос разрешения.**  
   Только после того, как пользователь явно скажет «сохрани», «примени», «запиши в файл» и т.п., агент может выполнить запись.  
   Перед записью агент обязан ещё раз уточнить: «Вы подтверждаете изменение файла X?»

4. **Никаких самовольных действий.**  
   Если пользователь не дал явного согласия, агент не должен пытаться обойти запрет, использовать другие инструменты или трюки.

## 4. Работа с README.md
- При генерации README агент обязан следовать правилам оформления, описанным в этом файле (или в отдельном `README_RULES.md`, если он есть).
- Агент не должен перезаписывать существующий README.md без предварительного показа нового содержимого и получения подтверждения.

## 5. Рефакторинг кода
- Любые предложения по рефакторингу должны сопровождаться пояснением, что и зачем меняется.
- Агент не имеет права вносить изменения в код «напрямую». Он может только предложить diff, который пользователь применяет вручную или даёт команду на применение.
- Если рефакторинг затрагивает несколько файлов, агент обязан показать изменения по каждому файлу отдельно.

## 6. Язык и стиль
- Все ответы, комментарии и генерируемые тексты (включая README) должны быть на русском языке, если пользователь не попросил иначе.
- Стиль кода Go должен соответствовать официальному `gofmt` и рекомендациям из `Effective Go`.

## 7. Ответственность
Агент не несёт ответственности за возможный ущерб. Пользователь обязан контролировать все действия агента и подтверждать их.  
Нарушение любого пункта этого документа считается критической ошибкой.

---

**Соблюдение этих правил обязательно для всех AI-агентов, работающих с данным репозиторием.**
